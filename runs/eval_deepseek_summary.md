# DeepSeek (pi harness) vs LFM2 v7 — pinned 98-row holdout

Generated by `eval_deepseek_pi.mjs` (pi ModelRuntime, herdr tools from
`reference/herdr_schemas.json`) vs `eval_lfm2.py` (local adapter).

## Accuracy (pinned holdout: 82 expected + 16 off-topic)

| model | exact-call | tool-selection | off-topic |
|---|---:|---:|---:|
| LFM2 v7 (tuned LoRA, greedy) | **96.3%** (79/82) | **96.3%** | **100%** (16/16) |
| deepseek-v4-flash-vision-exp (thinking=high) | 56.1% (46/82) | 65.9% (54/82) | 50.0% (8/16) |

The tuned 350M model outperforms the frontier model by a wide margin on this
narrow planner task. DeepSeek tends to emit multi-step agentic tool sequences
(e.g. `pane_current` + `pane_layout` before a split) and to act on off-topic
prompts, both of which the eval penalizes.

## Cost (98 rows)

| model | API cost | note |
|---|---:|---|
| LFM2 v7 | **$0** | local inference (CPU ~50 s/row ≈ 82 min; or Colab T4 <$0.01) |
| deepseek-v4-flash-vision-exp | **$0.0069** total ($0.00007/row) | $0.0019 input + $0.0007 cache-read + $0.0043 output |

DeepSeek's prompt caching (cache-read $0.0028/M vs input $0.14/M) makes the
shared tool-schema prefix essentially free after the first request.

## Bottom line

- DeepSeek: **$0.0069** and **293,281 tokens** to run the whole 98-row holdout.
- LFM2: **$0** API and **~266,300 tokens**, but requires local/Colab compute and
  its 681 MB weights + LoRA adapter — and it scores 96.3% vs 56.1%.
